Subagents — Definition

What exactly is a subagent?

A subagent is a child Claude instance spawned within your session via the Agent tool (previously called Task tool, renamed in v2.1.63). It gets its own context window, system prompt, and tool permissions — but runs inside the same process.

How it works internally

Subagent works independently. Only sees its prompt + CLAUDE.md + project files

💡
Key constraint: Subagents cannot spawn their own subagents. No nesting. If you include Agent in a subagent's tools array, it will be ignored.
🔑
The parent→child channel: The only way to pass context to a subagent is through the Agent tool's prompt string. No conversation history is inherited. Include file paths, error messages, decisions — everything it needs.

Subagents — Custom Agents

Build your own specialists

Custom subagents are Markdown files with YAML frontmatter. Place them in .claude/agents/ and Claude auto-discovers them. You can also get them from installed plugins.

docs/sub-agents#creating
.claude/agents/security-auditor.md
--- name: security-auditor description: MUST BE USED for security review of authentication, payment, and data handling code. tools: - Read - Grep - Glob - Bash # for running scanners model: opus # critical code → best model --- You are a senior security auditor. ## Before any review: 1. Check your memory for known vuln patterns 2. Read CLAUDE.md for project auth architecture ## Focus areas: - SQL injection, XSS, CSRF - JWT handling & token expiration - Input validation & sanitization - Secrets in code / env vars - Dependency vulnerabilities ## Output format: For each finding: - Severity: CRITICAL | HIGH | MEDIUM | LOW - Location: file:line - Description: what's wrong - Fix: concrete code suggestion ## After completing review: Save new patterns to your memory for future reference.
⚡
Quick start: Run /agents → Create new → describe what it does. Claude generates the Markdown file for you. You can also ask Claude to "generate a subagent definition."
Subagents — Configuration

Key configuration options

model — cost control

haiku for exploration (fast, cheap), sonnet for standard work, opus for critical decisions. This is a huge cost lever most people miss.

tools — principle of least privilege

Only grant what's needed. A reviewer shouldn't have Write. An explorer shouldn't have Bash. Restricting tools prevents accidents and reduces cost.

description — routing is everything

Claude uses this to decide when to delegate. Write "MUST BE USED for X" to strongly trigger on matching tasks. Vague descriptions = agent never gets invoked.

memory — persistent learning

project (shared via git — team benefits), user (in ~/.claude/agent-memory/ — personal), local (gitignored). The agent builds knowledge over time across sessions.

🧠
Persistent memory: When memory: project is set, the agent gets its own .claude/agent-memory/<name>/MEMORY.md. First 200 lines are injected into context at startup. The agent builds knowledge across sessions — learning your codebase patterns, past reviews, known issues. Git-tracked = your whole team benefits.

Where agents live

CLI flag: --agents JSON → session only (highest priority)
project: .claude/agents/*.md → git tracked
user:    ~/.claude/agents/*.md → all projects
plugin:  installed plugins → lowest priority
Priority: CLI flag > project > user > plugin. Name conflicts resolved by scope.

Subagents — Prompt Craft

Vague vs structured prompts

Vague prompt

"Review this code for issues"
Agent wanders across the entire repo, reads unrelated files, returns generic advice like "add error handling" and "improve naming." Wastes ~40K tokens.

Structured prompt

"Review src/routes/checkout.ts for race conditions. Focus on concurrent cart updates. Output: severity, file:line, issue, fix."
Agent reads exactly 2 files, finds the critical double-charge bug, returns structured findings with line numbers and fix code. Uses ~8K tokens.
The 5x rule: A structured prompt with all 5 elements typically uses ~5x fewer tokens than a vague one — because the agent doesn't waste context exploring irrelevant files.
Front-load context. The agent sees only your prompt — not your conversation history. Include file paths, tech stack, and relevant context explicitly.
Specify output format. Structured output (JSON, markdown tables, severity levels) enables downstream processing and makes results composable across agents.
Set constraints. Scope the agent to specific directories, file types, or concerns. Without constraints, agents explore broadly — burning tokens and context window.

Advanced prompting patterns

The Interview Pattern

"I want to build [brief description]. Interview me using AskUserQuestion. Ask about implementation, edge cases, tradeoffs. Then write a spec to SPEC.md"
Start fresh session to execute spec with clean context. Prevents overloading one session with both design and implementation.

Power-user prompting tricks

"Grill me on these changes — don't PR until I pass your test"
"Prove to me this works" — forces verification with branch diffs
"Scrap this and implement the elegant solution" — resets approach
"Use subagents to investigate X" — explicit delegation trigger

Subagents — API Surface

All 14 frontmatter fields

name required
string
Unique identifier. Lowercase + hyphens only. Enables SendMessage({to: name}) for follow-ups.
description required
string
Routing trigger. Claude matches tasks to agents by this. Tip: "MUST BE USED for X" forces auto-delegation.
tools opt
list
Allowlist. Agent(worker, researcher) restricts which subagents it can spawn. disallowedTools applied first.
model opt
enum
haiku | sonnet | opus | full model ID | inherit (default). Biggest cost lever.
maxTurns opt
number
Hard stop after N agentic turns. Prevents runaway agents. No default = unlimited.
effort opt
enum
low | medium | high | max. Opus 4.6 only. Controls adaptive thinking token budget.
background opt
boolean
Non-blocking. Gotcha: background agents auto-deny clarifying questions and only use pre-approved permissions.
isolation opt
enum
"worktree" = own git branch. Auto-cleaned if no changes. Transcripts at ~/.claude/projects/.../subagents/
memory opt
enum
project (git-tracked) | user (~/.claude) | local (gitignored). Auto-enables Read/Write/Edit tools.
skills opt
list
Skills full-injected into context at startup (not lazy-loaded). Consumes context tokens.
initialPrompt opt
string
Auto-submitted as first user turn only with --agent flag (main session agent). Commands and skills processed. Prepended to user-provided prompt.

Scope priority: CLI flag (--agents JSON) > project (.claude/agents/) > user (~/.claude/agents/) > plugin. Project-level overrides user-level on name conflict.

Click the steps below to walk through the SendMessage pattern. Each step highlights the relevant code.
Step 1 / 4
Why this matters:
Without SendMessage: You'd need to re-spawn the agent, losing all context from the first review. The agent starts from zero.
With SendMessage: The agent keeps its full context — every file it read, every finding it made. The follow-up builds on prior work.
⚡
Key insight: Named agents persist within your session. SendMessage continues the conversation without re-spawning or losing the agent's accumulated context. Think of it as a running service you can query multiple times.

Subagents — Security

Auto mode deep dive

Classifier: A separate Sonnet 4.6 model evaluates each action. Costs extra tokens. Adds round-trip latency.
Decision order: 1) Allow/deny rules resolve immediately → 2) Read-only + working dir file edits auto-approved → 3) Everything else → classifier → 4) If blocked, Claude retries differently
Security: Classifier does NOT see tool results — hostile file content can't manipulate it via prompt injection.
Subagents: If parent is in auto mode, subagent's own permissionMode frontmatter is ignored. Classifier gates the subagent's tool calls independently.
Fallback: 3 blocks in a row OR 20 total in session = auto mode pauses, falls back to manual prompts. Approving resets counters.
Auto mode drops these allow rules
// These get stripped for safety: Bash(*) // arbitrary code execution Bash(python*) // wildcarded interpreters Bash(node*) // wildcarded interpreters Agent // unrestricted spawning // These are PRESERVED: Bash(npm test) // narrow = ok Bash(git *) // scoped = ok
Subagents — Security

Plan mode & security layers

Plan mode — 4 approval paths

1. Approve + start auto mode

Plan approved, switches to auto mode for execution. Classifier gates all actions.

2. Approve + accept edits

Plan approved, switches to acceptEdits. File writes auto-approved, bash still prompts.

3. Approve + manual review

Plan approved, stays in default mode. Every action requires your approval.

4. Keep planning

Not ready yet. Iterate on direction, ask more questions. Stays in plan mode.

⚠️
bypassPermissions: No classifier, no checks. All actions execute immediately. Only for isolated containers/VMs. Admin can disable: "disableBypassPermissionsMode": "disable"
Mode switching:
⇧Tab cycles: default → acceptEdits → plan → auto
auto only appears with --enable-auto-mode + Team plan
dontAsk never in cycle — CLI only: --permission-mode dontAsk
🔒
OS-level sandbox: Beyond permission modes, use /sandbox for OS-level isolation. Controls filesystem access (allowWrite/denyWrite/denyRead), network (allowedDomains), and excluded commands. Configured in settings.json under sandbox.
Trail of Bits 3-layer security: 1) Built-in sandbox (Seatbelt on macOS, bubblewrap on Linux) 2) Permission deny rules for ~/.ssh/**, ~/.aws/**, ~/.npmrc, ~/.git-credentials 3) Devcontainers / disposable droplets for untrusted code. Also: "enableAllProjectMcpServers": false to block malicious MCP in compromised repos. trailofbits/claude-code-config

Context window management

Subagents aren't just for parallelism — they're a context management strategy. Each subagent's intermediate work is discarded; only the final message returns.

Worktree isolation for subagents

Not just for Agent Teams. Individual subagents can get their own git worktree via isolation: "worktree". Most devs don't know this exists. You can also start your entire session in a worktree with claude --worktree feature-name.

Deep Dive

Default vs isolated worktrees

isolation: none (default)

+ Instant spawn (no git ops)
+ Changes visible immediately
- Shares parent's workdir
- Risk: file conflicts with parent
- Risk: dirty git state
Use for: Read-only tasks (Explore, Plan), quick edits to non-overlapping files

isolation: "worktree"

+ Own git branch
+ Zero conflict with parent
+ Auto-cleanup if no changes
+ Changes reviewable as branch diff
- Slower spawn (~5-10s)
Use for: Write-heavy tasks, parallel agents editing similar files, risky refactors

Gotchas & Developer Tips

Things that will bite you

docs/best-practices#failure-patterns

🧠 Context is NOT inherited Critical

Subagents and teammates start with a blank conversation. Only the spawn prompt + CLAUDE.md carry over. 20 messages of architecture discussion? Gone.

Agent asks "what project is this?" or re-reads files you already discussed.
Only the prompt string passes to subagents — no conversation history.
// Include context explicitly in the prompt Agent({ prompt: "Project: Node.js e-commerce API.\nFiles: src/auth/...\nReview for SQL injection." })

🔇 Background agents auto-deny questions Warning

background: true agents can't ask clarifying questions — they auto-deny them. Only pre-approved permissions execute.

Background agent silently skips tasks or returns incomplete results.
Background mode auto-denies all interactive prompts. MCP tools needing approval also fail.
// Fix: ensure all permissions pre-approved Agent({ prompt: "...", run_in_background: true, mode: "acceptEdits" })

📝 disallowedTools applies FIRST Warning

Resolution order: disallowedTools removes from pool → tools selects from remaining. Deny always wins.

Agent can't use a tool you explicitly listed in tools:.
disallowedTools is checked first, stripping tools before tools allowlist runs. Also: parent's bypassPermissions can't be overridden by subagent.
// Fix: check both lists aren't conflicting tools: [Bash, Read, Edit] disallowedTools: [] # ensure Bash isn't here

📁 Transcripts persist separately Note

Subagent conversations stored at ~/.claude/projects/{project}/{session}/subagents/. They survive parent compaction.

Disk space grows unexpectedly; old transcripts piling up.
Each subagent writes its own transcript file. Cleaned per cleanupPeriodDays (default: 30 days).
// Location: ~/.claude/projects/{hash}/{session}/subagents/agent-{id}.jsonl // Manually clean: rm -rf ~/.claude/projects/*/transcripts/

🪟 No session resume for teams Critical

/resume doesn't restore in-process teammates. Teams are fire-and-forget.

After disconnect, teammates are orphaned. tmux sessions linger consuming resources.
Team processes run independently. No reconnect mechanism exists yet.
// Clean up manually tmux kill-session -t team-name // Split panes fail in: VS Code terminal, Windows Terminal, Ghostty

💉 Skills are full-injected Warning

The skills field injects full skill content into the subagent's context at startup — consuming tokens immediately.

Haiku subagent runs out of context fast, or costs more than expected.
Each skill is injected in full at spawn time, not lazily loaded. 10 skills = 10x the startup cost.
// Fix: only include essential skills skills: ["security-review"] # not all 10 skills // Use initialPrompt (--agent flag only) for pre-spawn guidance
Gotchas & Developer Tips

Operational gotchas

👑 Lead won't delegate without nudging Warning

Claude's default: do work itself. Say "do NOT implement, only coordinate" or use delegate mode.

Team lead does all the work instead of distributing to teammates.
Without explicit instructions, Claude prefers to work alone rather than delegate.
// Fix: explicit delegation in your prompt "You are the LEAD. Do NOT implement anything yourself. Decompose into tasks and assign to teammates."

🔄 Auto mode classifier Note

Classifier doesn't see tool results (prevents prompt injection). Strips Bash(*) and Agent allow rules.

Auto mode blocks safe operations, or pauses entirely mid-task.
After 3 consecutive blocks or 20 total, auto mode pauses. Requires --enable-auto-mode flag.
// Fix: use narrow allow rules allowedTools: ["Bash(npm test)", "Bash(git *)"] # scoped = OK // NOT: Bash(*) # auto mode strips wildcards

🪝 Team quality hooks Note

TeammateIdle and TaskCompleted hooks let you enforce quality gates on team operations.

Teammates idle prematurely or mark tasks done without tests passing.
Without hooks, there's no automated quality enforcement for team workflows.
// TeammateIdle: exit code 2 → sends feedback to keep working // TaskCompleted: exit code 2 → prevents completion // Great for: "run tests before marking done"

📝 CLAUDE.md gets silently deprioritized Warning

Claude's system prompt says CLAUDE.md content "may or may not be relevant." Only universally applicable instructions survive this filter. Keep under 200 lines.

Claude ignores your CLAUDE.md instructions, especially long or domain-specific ones.
System prompt tells Claude to treat CLAUDE.md as optional context. LLMs reliably follow ~150-200 instructions; beyond that, quality drops uniformly.
// Fix: progressive disclosure strategy // Keep CLAUDE.md short with pointers: // "See @docs/conventions.md for code style" // "See @docs/testing.md for test patterns" // Use .claude/rules/*.md for domain-specific rules // "Never send an LLM to do a linter's job" — HumanLayer

🍳 Kitchen-sink sessions Warning

Mixing unrelated tasks in one session degrades performance as context fills with irrelevant history. Per Anthropic's best practices doc.

Claude starts forgetting earlier decisions, responses become slower and less accurate.
Context window fills with irrelevant conversation history from previous unrelated tasks.
// Fix: /clear between unrelated tasks // After 2 failed corrections: /clear + better prompt // Use /compact with instructions to focus context

🔁 Correction loops Warning

Correcting Claude over and over gets worse, not better. After 2 failed attempts, /clear and restart with a more specific prompt.

Each correction attempt produces worse results. Claude seems to "try harder" in the wrong direction.
Previous failed attempts pollute the context, compounding confusion.
// Fix: after 2 failures, /clear and start fresh // Include: exact file paths, constraints, expected output format // "Explore first, plan, then implement" approach works better

Don't just say "refactor auth." Decompose into explicit agent steps. Claude is more aggressive with subagents when you tell it to decompose.

"Decompose this into subagent steps: 1. Explore agent → map the codebase 2. Plan agent → design the approach 3. Await my approval 4. Implement with background test runner agent in parallel"
03

Run your first Agent Team

Pick a multi-module task you've been putting off. Enable the flag, open tmux, and give Claude a specific team structure. Use delegate mode.

# settings.json { "env": { "CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS" : "1" }} # Then: tmux → claude → describe team
